# WEEK 12 TASKS — 최종 주차: 자체 QA 셋 구축 · 다각도 평가 · 프로젝트 결론

> **마지막 주차다.** 새 기능을 벌이는 주가 아니라 **닫는 주**다. 12주간의 주장을 스스로 검증하고, 남는 문서(README·ADR-012)로 마감한다.
> **이번 주의 중심 원칙:** RAGAS 같은 자동 지표에 의존하지 않는다. **직접 만든 QA 셋 + 다각도 렌즈 + 수동 채점**으로, 발표자가 "왜 이런 결과인지"를 직접 설명할 수 있게 한다. **성급한 결론을 내리지 않는다** — 표본이 작으면 작다고 쓰고, 말할 수 있는 것과 없는 것을 명시적으로 나눈다.
> 선행: `docs/week11_architecture.md`(§7 region-crop MVP), `docs/week9_evaluation.md`, `data/eval/golden_set_v3.csv`.

## 0. 왜 이 순서인가 (진단)

지금까지 모든 결론이 **표본 부족**에 걸려 있다. 현재 `golden_set_v3.csv` 41문항 중:

- **image-required = 7문항뿐** (IR-W2는 audit에서 강등). 1문항이 14%p라 어떤 비교도 노이즈와 구분 불가.
- 그 7문항이 **complex 매뉴얼 3종·5개 페이지**에서만 나왔다. **simple 매뉴얼 3종은 image-required 0문항** — 데이터의 절반이 측정에서 빠져 있다.
- Week 9의 "IR-W1 첫 승리", Week 11의 "crop이 사선을 잡았다"는 **전부 n=1 관찰**이다. 방향 증거일 뿐 결론이 아니다.

따라서 12주차는 **① QA 셋을 먼저 키우고 → ② region-crop을 검색에 연결하고 → ③ 다각도로 재평가 → ④ 그 결과로만 결론(ADR-012)** 순서로 간다. 순서를 바꾸면 또 n=1 결론이 나온다.

## 2. [P0-A] 자체 QA 셋 v4 — 이번 주의 핵심

> 산출물: `data/eval/golden_set_v4.csv` (v3 41문항 유지 + image-required 확장). **자동 생성 금지 — 원본 PDF를 보고 직접 만든다.**

### 2.1 목표 구성

| modality | 현재(v3) | 목표(v4) | 비고 |
|---|---|---|---|
| image-required | 7 | **24** | 6개 매뉴얼 × 4유형 = 24 (아래 2.2) |
| image-helpful | 7 | 7~10 | 대조군(그림이 도움은 되나 필수는 아님) |
| text-only | 27 | 27 | v3 유지 (이미 수리 완료) |

**24문항이 목표인 이유:** 유형별 6문항이 되어야 "위치 질문은 되는데 아이콘은 안 된다" 같은 **유형별 진술**이 가능해진다. n=6이어도 작지만, 1문항=17%p라 최소한 경향은 읽힌다. 시간이 부족하면 **매뉴얼 6종 × 2유형 = 12문항이 최소선**.

### 2.2 유형 4종 (Week 11 crop이 겨냥한 능력과 1:1 대응)

| 유형 | 묻는 것 | 예시 | crop이 잡아야 할 필드 |
|---|---|---|---|
| **위치** | 부품이 제품의 어디에 있나 | "조작부는 앞면 어느 쪽?" | `position_in_figure` |
| **배치/콜아웃** | 번호가 가리키는 게 무엇인가 | "①번 자리에 끼우는 필터는?" | `label` |
| **방향** | 어느 쪽으로 돌리나/끼우나 | "거치대는 어느 방향으로?" | `direction` |
| **아이콘 모양** | 그 표시가 어떻게 생겼나 | "연결 끊김은 어떤 모양?" | `shape` |

### 2.3 작성 규칙 (Week 9 audit에서 배운 것)

1. **원본 PDF를 열어 직접 확인**하고 만든다. 추측 금지.
2. **본문 텍스트에 답이 없는지 반드시 대조** — 있으면 image-required가 아니라 image-helpful이다 (IR-W2가 강등된 이유).
3. **모델을 특정**한다 ("정수기"가 아니라 "WD520AWB 정수기") — simple/complex가 정답이 달라지는 문제(Q19) 재발 방지.
4. `reference_context`(모델 p.N (섹션명)) + `figure_ref`(모델 p.N fig:이름) 규약 유지.
5. **simple 매뉴얼 3종을 반드시 포함** — 현재 0문항. 복잡한 매뉴얼에서만 되는 건지 구분해야 한다.
6. GT는 **매뉴얼 원문 표현**으로 쓴다. 모호하게 쓰면 채점이 흔들린다.

### 2.4 검증

- 24문항 각각에 대해 "이 답이 본문에 있는가?" 체크 컬럼(`text_has_answer`)을 남긴다 — 나중에 라벨 신뢰도의 근거가 된다.
- 유형·매뉴얼별 분포표를 `docs/week12_evaluation.md` 첫 절에 싣는다.

## 3. [P0-B] region-caption을 검색에 연결

> Week 11에서 crop 캡션은 만들었으나 **검색에 안 붙였다.** 이번에 붙여야 비교가 성립한다.

- `region_caption_to_document`(Week 11에 준비됨)로 crop 캡션을 청크화 → **mm 스토어 리빌드**.
- 검색 구성 3종 확정:
  - **C0** = 텍스트만 (baseline)
  - **C1page** = 텍스트 + 페이지 캡션 (Week 9 방식)
  - **C1region** = 텍스트 + **영역 캡션** (이번 주 신규)
- v4의 24문항이 가리키는 페이지에 crop 캡션이 존재해야 한다 → **필요 페이지 crop 확대**(Week 11은 5페이지 12영역뿐). 없는 페이지는 결과 해석에서 제외하거나 crop을 추가한다. **어느 쪽인지 문서에 명시.**

## 4. [P0-C] 다각도 평가 — 6개 렌즈

> 산출물: `data/week12_results.json`, `docs/week12_evaluation.md`. **RAGAS 사용 안 함.** 전부 직접 정의한 렌즈 + 수동 채점.

### 4.1 렌즈 6종 (각각 "무엇을 말해주는가"를 함께 적는다)

| # | 렌즈 | 측정 | 이 렌즈가 답하는 질문 |
|---|---|---|---|
| L1 | **검색 도달** | 정답 페이지가 top-k에 들었나 | 못 맞힌 게 검색 탓인가? |
| L2 | **근거 도달** | 정답 캡션(페이지/영역)이 컨텍스트에 들었나 | 그림 정보가 실제로 전달됐나? |
| L3 | **답변 정확도** (수동 채점) | 매뉴얼 대비 사실이 맞나 | 최종 사용자가 원하는 답이 나왔나? |
| L4 | **거절 품질** | 모를 때 정직히 거절했나 / 지어냈나 | 안전한가? |
| L5 | **실패 원인 분류** | 아래 4.2 분류표 | 왜 실패했나? (개선 방향) |
| L6 | **비용·지연** | 문항당 소요시간·호출 수 | 실용적인가? |

**L3 채점 기준:** "GT 문자열 일치"가 아니라 **매뉴얼 충실성**(원본 대비 사실이 맞는가). Week 9에서 엄격 judge가 GT 결함 때문에 false negative를 낸 교훈. 채점자는 본인이며, 애매한 건 **애매하다고 표기**(0/1 강제하지 않음: 정답/부분/오답/거절 4단계 권장).

### 4.2 실패 원인 분류표 (L5)

실패한 문항마다 아래 중 하나로 태깅 — **이게 발표에서 "왜"를 설명하는 재료다.**

| 코드 | 원인 | 대응 방향 |
|---|---|---|
| F-RET | 검색이 정답 페이지를 못 찾음 | 검색 개선 |
| F-CAP | 페이지는 찾았으나 캡션에 그 정보가 없음 | crop 필요 (Week 9 병목) |
| F-CROP | 영역 캡션에도 없음 (검출 실패/영역 밖) | 영역 검출 개선 |
| F-GEN | 근거는 있었으나 답을 못 만듦 | 프롬프트/생성 |
| F-GT | 정답지 자체가 문제 | QA 셋 수정 |

### 4.3 비교표 (채울 것)

| 구성 | L1 검색도달 | L2 근거도달 | L3 정답 | L3 부분 | L4 거절적절 | 주요 실패원인 |
|---|---|---|---|---|---|---|
| C0 텍스트만 | | | | | | |
| C1page 페이지캡션 | | | | | | |
| C1region 영역캡션 | | | | | | |

**유형별(위치/배치/방향/아이콘) 분해표도 함께** — "아이콘은 crop이 뚫었고 위치는 아직"처럼 유형별로 말할 수 있어야 한다.

### 4.4 성급한 결론 방지 장치 (필수)

`docs/week12_evaluation.md`에 **"주장 가능/불가 목록"** 절을 만든다:

- **말할 수 있는 것:** 어떤 수치가 몇 문항 기준으로 어떤 차이를 보였는지.
- **말할 수 없는 것:** 표본 크기 때문에 단정 못 하는 것, 통제 안 된 변수(예: crop이 일부 페이지에만 있음), 채점자가 본인이라 생기는 편향.
- **각 주장 옆에 n을 반드시 병기.** "정답률 향상"이 아니라 "24문항 중 8→13(n=24)".

## 5. [P0-D] ADR-012 — 크로스모달 최종 결론

> 산출물: `adr/ADR-012-crossmodal-conclusion.md`. Week 9부터 의도적으로 미뤄온 문서. **12주 프로젝트의 마침표.**

템플릿(`adr/ADR-000-template.md`) 형식 유지. 내용:

- **상황:** 텍스트 전용 RAG가 도면 질문에서 무너짐(ADR-011 앵커 model 50%/page 25%) → cross-modal 필요.
- **고려한 선택지와 결과:** CLIP 이미지 임베딩(기각, 근거: Week 9 §5) / 페이지 단위 VLM 캡션(부분 성공, 한계: 아이콘·위치·방향) / **영역 단위 VLM 캡션**(이번 주 측정) / 질의 시점 Vision 에스컬레이션(Week 11: full-page로는 한계 재현).
- **결정:** 이 도메인(한국어 vector line-art 매뉴얼)의 cross-modal 경로는 무엇인가 — **측정 결과에 근거해서만 쓴다.**
- **이유:** §4 표를 인용. n 병기.
- **한계와 향후:** 표본 크기, 미해결 유형, 실무 적용 시 고려사항.

> **주의:** 결과가 기대에 못 미쳐도 그대로 쓴다. "crop이 모든 걸 해결했다"가 아니라 실제 수치가 말하는 것만. 12주간 이 프로젝트의 미덕은 정직한 측정이었다.
