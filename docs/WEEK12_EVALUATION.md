# WEEK 12 EVALUATION — 자체 QA 셋 v4 기반 3-way 크로스모달 평가

> 산출물: `data/week12_results.json`, `data/week12_scores.json`, `data/week12_grading_sheet.md`
> 실행: `.venv/bin/python -m src.week12_eval C0 | C1page | C1region | sheet | merge`
> **RAGAS·LLM judge 사용 안 함.** 답변 채점은 원본 매뉴얼 페이지를 직접 대조한 수동 4단계 채점이다.

---

## 1. 무엇을 측정했나

| 구성 | 컨텍스트 | 스토어 |
|---|---|---|
| **C0** | 텍스트 청크 top-5 | `chroma_db_c3` |
| **C1page** | 텍스트 3 + **페이지 캡션** 2 | `chroma_db_mm_w12` (`caption_scope="page"`) |
| **C1region** | 텍스트 3 + **영역 캡션** 2 | `chroma_db_mm_w12` (`caption_scope="region"`) |

세 구성 모두 **컨텍스트 5청크·답변 모델 gpt-4o-mini·동일 질문셋**으로 통제했다.
C1page와 C1region은 **같은 스토어의 서로 다른 필터**다 — 텍스트 레인은 완전히 동일하고
캡션 종류만 다르다. 스토어를 둘로 나누면 텍스트 레인까지 달라져 비교가 오염된다.

### 1.1 질문 셋 (golden_set_v4.csv)

v3 41문항 → **v4 61문항** (text-only 27 유지 + image-helpful 7 유지 + **image-required 7 → 27**).
image-required 27문항은 전부 원본 PDF 페이지를 직접 열어보고 작성했다 (자동 생성 없음).

| 매뉴얼 | 위치 | 배치 | 방향 | 아이콘 | 계 |
|---|---|---|---|---|---|
| airpurifier_complex (AS281DAW) | 2 | 1 | 1 | 1 | 5 |
| airpurifier_simple (AS181DAW) | 1 | 1 | 0 | 2 | 4 |
| waterpurifier_complex (WD520A) | 1 | 1 | 0 | 2 | 4 |
| waterpurifier_simple (WD325A) | 1 | 1 | 0 | 2 | 4 |
| vacuumcleaner_complex (O958) | 0 | 2 | 2 | 1 | 5 |
| vacuumcleaner_simple (K83) | 2 | 2 | 1 | 0 | 5 |
| **계** | **7** | **8** | **4** | **8** | **27** |

- 참조 페이지 15개, `text_has_answer` = no 23 / partial 4.
- **simple 매뉴얼 3종이 13문항** — v3에서는 0문항이었다 (§5의 "말할 수 있는 것"이 늘어난 핵심 이유).
- 평가 실행은 image-required 27 + text-only 대조 6 (Q01/Q06/Q08/Q11/Q18/Q19, Week 9와 동일) = **33문항 × 3구성 = 99회**.

### 1.2 유형 분포가 고르지 않은 이유 (데이터의 성질)

**방향이 4문항뿐인 것은 게으름이 아니라 소스의 성질이다.** 정수기 매뉴얼은 회전 방향을
본문에 명시한다("필터 끝부분을 들어올린 후 **반시계 방향으로** 돌려 분리하세요"). 이런 문항은
정의상 image-required가 아니라 image-helpful이다. 6개 매뉴얼 전체에서 본문이 방향을 명시적으로
도면에 위임한 사례는 `vacuumcleaner_complex p.17` **"화살표 방향으로 여세요"** 단 한 곳이다(IR-V4).
청소기 매뉴얼만 방향을 도면에 맡기고, 정수기·공기청정기는 본문에 적는다.

vacuumcleaner_simple(K83)에 아이콘 문항이 0인 것도 같은 이유다 — 유선 청소기라 표시창이 없다.

## 2. 렌즈 6종 결과 (image-required, n=27)

| 렌즈 | C0 | C1page | C1region |
|---|---|---|---|
| **L1** 매뉴얼 도달 | 100% (27/27) | 100% (27/27) | 100% (27/27) |
| **L1** 페이지 도달(±2p) | 96% (26/27) | 93% (25/27) | 96% (26/27) |
| **L2** 캡션 도달 | n/a (캡션 없음) | 89% (24/27) | 93% (25/27) |
| **L3** 정답 | **0/27** | **1/27** | **8/27** |
| **L3** 정답+부분 | **0/27** | **5/27** | **12/27** |
| **L4** 거절 | 23 (전부 적절) | 17 (전부 적절) | 13 (적절 8 / **부적절 5**) |
| **L6** 문항당 지연 | 24.3s | 25.1s | 25.7s |

L3 4단계 분해:

| 구성 | 정답 | 부분 | 오답 | 거절 |
|---|---|---|---|---|
| C0 | 0 | 0 | 4 | 23 |
| C1page | 1 | 4 | 5 | 17 |
| C1region | **8** | 4 | 2 | 13 |

### 2.1 이 표가 말하는 것

**검색은 문제가 아니었다.** 세 구성 모두 L1 매뉴얼 도달 27/27, 페이지 도달 25~26/27이다.
C0는 정답 페이지를 거의 항상 찾고도 27문항 중 23문항을 거절했다 — **"페이지는 찾았지만 그
페이지의 텍스트에 답이 없다"**를 정직하게 인정한 것이다. image-required 라벨링이 옳았다는
독립적인 증거이기도 하다: 텍스트만으로 답할 수 있었다면 C0가 답했을 것이다.

**따라서 병목은 검색이 아니라 "그림 속 정보가 텍스트로 존재하는가"였다.** L5 원인 분포가 그대로 보여준다.

## 3. 유형별 분해 (§4.3) — 이번 주의 가장 중요한 표

정답 수 / (정답+부분) 수, n은 유형별 문항 수.

| 유형 | n | C0 | C1page | C1region |
|---|---|---|---|---|
| **아이콘** | 8 | 0 / 0 | 0 / 2 | **6 / 7** |
| **배치** | 8 | 0 / 0 | 1 / 2 | 1 / 3 |
| **위치** | 7 | 0 / 0 | 0 / 1 | 1 / 2 |
| **방향** | 4 | 0 / 0 | 0 / 0 | **0 / 0** |

**영역 캡션이 뚫은 것은 사실상 아이콘 한 유형이다** (8문항 중 6문항 정답). 나머지 세 유형은
n이 작아 경향 수준이지만, 방향은 **세 구성 모두 0/4로 완패**했다 — 유일하게 모든 구성이
같은 값을 낸 유형이고, 표본이 작아도 "안 된다"는 진술은 할 수 있다.

매뉴얼 복잡도별 (정답+부분):

| | n | C0 | C1page | C1region |
|---|---|---|---|---|
| simple 3종 | 13 | 0 | 2 | 5 |
| complex 3종 | 14 | 0 | 3 | 7 |

simple에서도 complex에서도 같은 방향으로 움직였다. **"복잡한 매뉴얼에서만 되는 기법"은 아니다** —
v3의 image-required가 complex 3종에만 있었기 때문에 Week 9까지는 확인할 수 없던 사실이다.

## 4. L5 실패 원인 분류

| 코드 | 뜻 | C0 | C1page | C1region |
|---|---|---|---|---|
| F-RET | 검색이 정답 페이지를 못 찾음 | 1 | 2 | 1 |
| F-CAP | 페이지는 찾았으나 (페이지)캡션·텍스트에 그 정보가 없음 | 26 | 23 | 0 |
| F-CROP | 영역 캡션에도 없음 (검출 실패/영역 밖/캡션 부정확) | 0 | 0 | 12 |
| F-GEN | 근거는 컨텍스트에 있었는데 답을 못 만듦 | 0 | 1 | 6 |
| F-GT | 정답지 자체의 문제 | 0 (대조군 Q08에서 1) | 0 | 0 |

> C0에는 캡션이 없으므로 C0의 F-CAP은 "찾은 텍스트 청크에 정보 없음"으로 읽는다.

**실패의 성격이 바뀌었다.** C0/C1page의 실패는 압도적으로 F-CAP(정보 자체가 인덱스에 없음)인데,
C1region에서는 F-CAP이 0이 되고 F-CROP 12 + **F-GEN 6**으로 갈린다.

### 4.1 F-GEN 6건 — 가장 아까운 실패

C1region에서 **근거가 컨텍스트 안에 있었는데도 답하지 못한 문항이 6건**이다. 예:

- **IR-A5** (AS181DAW 조작부 위치) — 컨텍스트에 `조작부 · 원형, 내부에 기호 · 제품 상단`이 있었는데 거절.
- **IR-W7** (안심살균 버튼 위치) — 컨텍스트에 `안심살균 · 원, 내부에 'UVnano' · 오른쪽 하단`이 있었는데 거절.
- **IR-V8** (먼지통 분리 버튼 위치) — 컨텍스트에 `버튼 … 제품 상단`이 있었는데 거절.
- **IR-A9** (포장용 지지대 방향) — 컨텍스트에 `포장용 지지대 · 제품 하단 앞면 · 지지대를 왼쪽으로 분리`가 있었는데 거절.
- **IR-V4** (충전대 뚜껑 방향) — 컨텍스트에 `1 · 화살표 · 제품 윗면 · **조작부를 위로 열기**`가 있었는데도
  답변은 "화살표 방향으로 열어야 합니다"라는 동어반복. C1page도 같은 실패였다(페이지 캡션에
  "위쪽으로 향하는 화살표"가 있었다).

즉 **C1region의 상한은 12/27이 아니라 그 위에 있다.** 다만 이 6건이 자동으로 정답이 된다는
보장은 없으므로(§5 "말할 수 없는 것"), 여기서는 "생성 단계에 개선 여지가 있다"까지만 말한다.

### 4.2 F-CROP 12건 — 영역 캡션의 실제 한계

- **캡션에 항목이 통째로 빠짐**: `airpurifier_complex p.18` 영역 캡션은 배출구·흡입구·표시등만 나열하고
  상태 표시부·조작부·리모컨 수신부를 빠뜨렸다 → IR-A1/A2/A4 전부 거절.
- **캡션 내용이 틀림**: IR-V2에서 영역 캡션이 거치대를 `왼쪽으로 회전`으로 기술했다(정답은 시계방향).
  이때 시스템이 **거절한 것은 다행**이다 — 틀린 방향을 자신 있게 답하는 것보다 안전하다.
- **inset 내부 텍스트 미포착**: IR-V7(최강→강→중→약→정지 순서)은 확대 inset 안의 라벨이라
  영역 캡션에 들어오지 않았다. 영역 검출이 지시선으로 이어진 합성 도면을 하나의 덩어리로 묶기 때문에
  inset이 독립 영역으로 분리되지 않는다(dilate 0/1/2 전부 확인 — 현재 값이 가장 잘 쪼갠다).

## 5. 주장 가능 / 불가 목록 (§4.4)

### 말할 수 있는 것

1. 텍스트 전용 RAG는 이 27문항에서 **정답 0/27**이고, 그중 23문항은 정직하게 거절했다 (n=27).
2. 영역 캡션 구성은 정답 **8/27**, 정답+부분 **12/27**로, 페이지 캡션 구성(1/27, 5/27)보다 높았다 (n=27).
3. 이 이득은 **아이콘 유형에 집중**되어 있다 — 아이콘 8문항 중 6문항 정답 (n=8).
4. **방향 유형은 세 구성 모두 0/4 정답**이다 (n=4).
5. 세 구성 모두 **매뉴얼 도달 27/27** — 실패는 검색 실패가 아니다 (n=27).
6. 텍스트 전용 대조군 6문항에서 캡션 추가가 **정답 수를 떨어뜨리지 않았다** (세 구성 모두 정답 3/6, n=6).
7. 지연 비용은 무시할 만하다: C0 24.3s → C1region 25.7s, 문항당 **+1.4초 (+6%)** (n=33).
8. C1region의 거절 13건 중 **5건은 부적절**했다 — 근거가 컨텍스트에 있었다 (n=13).

### 말할 수 없는 것

1. **표본이 작다.** 유형별 n은 4~8이다. 1문항이 아이콘에서 12.5%p, 방향에서 25%p를 움직인다.
   "아이콘 75% 정답"은 8문항 기준의 관찰이지 성능 추정치가 아니다.
2. **채점자 편향.** 질문·정답지를 작성한 주체와 채점 주체가 같다(Claude Code 작성·채점, 사용자 스팟체크).
   GT를 쓸 때 본 것을 채점에서 다시 찾는 확증 편향을 배제할 수 없다.
3. **통제되지 않은 변수 — 크롭 범위.** 영역 캡션은 골든셋이 지목한 15페이지에만 존재한다.
   평가 질문이 전부 그 15페이지를 향하므로 C1region은 "항상 크롭이 있는" 유리한 조건에서 측정됐다.
   전체 252페이지로 확장했을 때 같은 이득이 유지되는지는 **측정하지 않았다**.
4. **인덱스 프롬프트를 이번 주에 바꿨다.** 영역 캡션 프롬프트에 (a) 페이지 전체 인쇄 텍스트를
   라벨 대조용으로 주고 (b) 지시선을 따라가라는 지시를 추가했다. Week 11 캡션과 직접 비교되지 않는다.
   (다만 Week 9 페이지 캡션 VLM은 같은 인쇄 텍스트를 페이지 이미지로 이미 보고 있었으므로
   두 구성 간 정보 비대칭은 아니다. 또한 `region_caption_to_document`는 캡션 필드만 색인하며
   원본 페이지 텍스트를 스토어에 넣지 않는다.)
5. **C1page는 Week 9의 C1과 같은 수가 아니다.** 이번 주에 캡션 예산 배분을 검색 순서 절단에서
   질의 기준 rerank로 바꿨다(영역 캡션이 region_idx라는 무관한 순서로 잘리는 것을 막기 위해,
   두 구성에 동일 적용). Week 9 대비 증감으로 읽으면 안 된다.
6. **부분 판정의 경계가 주관적이다.** 예: IR-A8에서 "시계 모양"은 정답의 핵심을 담았지만
   GT가 요구한 점선 테두리를 빠뜨려 부분으로 봤다. 다르게 채점하면 C1region 정답은 9/27이 된다.
7. `text_has_answer=partial` 4문항(IR-A6/W1/W6/V2)은 본문이 부분적으로 답을 준다.
   실제로 IR-W1은 C1page·C1region 모두 **캡션 없이 텍스트만으로** 정답을 맞혔다(caption_hit=False).
   순수 image-required로 보기 어렵다.

## 6. 비용 (L6)

- **질의 시점**: 문항당 LLM 호출 1회(생성), 지연 C0 24.3s / C1page 25.1s / C1region 25.7s.
  세 구성의 차이는 캡션 청크 rerank 비용 정도로 미미하다.
- **인덱스 시점 (일회성)**: 영역 검출·크롭 34개 + gpt-4o 캡션 34회 (15페이지, 페이지당 평균 2.3영역).
  페이지 캡션은 252페이지 × 1회(Week 9에 이미 지불). 영역 캡션은 페이지당 더 비싸지만
  **필요한 페이지에만 선택적으로 적용할 수 있다** — `targets_from_golden_set()`이 골든셋에서 대상
  페이지를 유도하므로, 실무에서는 "도면이 답을 갖는 페이지"만 크롭하면 된다.

## 7. 재현 방법

```bash
# 1) 영역 크롭 + 캡션 (골든셋 v4가 지목한 페이지 전체)
.venv/bin/python -m src.region_caption week12        # -> data/week12_captions_crop.json

# 2) mm 스토어 (텍스트 + 페이지캡션 + 영역캡션, caption_scope 태그)
.venv/bin/python -c "import json;from pathlib import Path;\
from src.multimodal import PageCaption, build_mm_store;\
build_mm_store([PageCaption(**r) for r in json.loads(Path('data/week9_captions_v2.json').read_text())],\
 Path('data/chroma_db_mm_w12'),\
 region_rows=json.loads(Path('data/week12_captions_crop.json').read_text()))"

# 3) 3구성 실행 (구성당 1프로세스 — 메모리)
.venv/bin/python -m src.week12_eval C0
.venv/bin/python -m src.week12_eval C1page
.venv/bin/python -m src.week12_eval C1region

# 4) 수동 채점용 시트 → data/week12_scores.json 작성 → 병합
.venv/bin/python -m src.week12_eval sheet
.venv/bin/python -m src.week12_eval merge
```
