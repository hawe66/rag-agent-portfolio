# WEEK 12 RETROSPECTIVE — 12주 전체 회고

> 마지막 주차 회고. 주차별 회고는 `docs/WEEK*_RETROSPECTIVE.md`에 있고, 여기서는 12주를 통으로 본다.

---

## 1. 무엇을 만들었나

한국어 LG 가전 매뉴얼 PDF 6종(252페이지)을 대상으로, **텍스트 RAG → 크로스모달 RAG → 에이전트**로
단계적으로 진화하는 시스템 하나와, 그 진화를 실제로 검증하는 **평가 체계**를 만들었다.

| 층 | 결과물 |
|---|---|
| 검색 | Hybrid(BM25+Dense, RRF) + cross-encoder rerank → Top-1 60.9% → **91.3%** |
| 추론 | LangGraph 4노드 Agentic RAG(retrieve→grade→rewrite→generate, retry≤2 후 거절) → **95.7%** |
| 평가 | RAGAS 4지표 + 도메인 메트릭(Refusal·Citation), modality·유형별 분해, 3분할 보고 |
| 크로스모달 | 페이지 rasterize → 영역 검출 → 300dpi 크롭 → VLM 구조화 캡션 → modality-aware 검색 |
| 에이전트 | tool 4종 + 3단 폴백(OCR / vision 재독 / 거절) |
| 데이터 | golden_set v1→v4, image-required 0 → 27문항 (전부 수작업) |

**최종 수치**(image-required 27문항, 수동 채점): 정답 C0 0/27 → C1page 1/27 → **C1region 8/27**.

## 2. 무엇을 배웠나

### 2.1 측정할 수 없으면 개선했는지도 알 수 없다

이 프로젝트에서 가장 많은 시간을 쓴 것은 모델이나 검색 알고리즘이 아니라 **평가셋과 평가 하네스**였다.
그리고 그게 옳았다. 12주차에 얻은 가장 중요한 수치는 "C1region 8/27"이 아니라
**"C0가 정답 페이지를 26/27 찾고도 23문항을 거절했다"**이다. 이 한 줄이

- 골든셋의 image-required 라벨이 옳았음을 증명하고(텍스트로 답할 수 있었으면 C0가 답했을 것),
- 병목이 검색이 아니라 정보의 존재 여부임을 확정하고,
- 크로스모달이 왜 필요한지를 수치로 설명한다.

11주 동안 이 문장을 쓸 수 없었던 이유는 단 하나, **image-required 문항이 7개뿐**이었기 때문이다.

### 2.2 "n=1 관찰"과 "결론"은 다르다

Week 9의 "IR-W1 첫 캡션 승리", Week 11의 "crop이 사선을 잡았다" — 둘 다 진짜 관찰이었지만
**전부 n=1**이었다. 그때 ADR-012를 썼다면 "영역 캡션이 크로스모달을 해결한다"고 썼을 것이다.
27문항으로 재보니 실제 결론은 훨씬 좁다: **아이콘 유형은 뚫었고(6/8), 방향은 못 뚫었다(0/4).**
ADR-012를 세 번 미룬 것은 이 프로젝트에서 잘한 판단 중 하나다.

### 2.3 안전한 실패가 위험한 성공보다 낫다

C0가 23문항을 거절한 것은 "실패"로 집계되지만 **정직한 실패**였다. 반대로 IR-V2에서 영역 캡션이
거치대 회전을 "왼쪽으로 회전"(정답: 시계방향)이라고 **틀리게** 기술했을 때, 시스템이 거절한 것은
운이 아니라 설계(근거 부족 시 거절)의 효과였다. 매뉴얼 도메인에서 틀린 조작 방향을 자신 있게
말하는 것은 모른다고 하는 것보다 명백히 나쁘다.

동시에 배운 반대편: **정보를 늘리면 안전성이 자동으로 좋아지지 않는다.** C1region은 거절 13건 중
5건이 부적절한 거절(근거가 있는데 거절)이었다. C0·C1page는 0건이었다.

### 2.4 도메인 지식이 기술 선택을 결정한다

- CLIP이 이 도메인에서 실패한 이유는 구현 버그가 아니라 **선화 도면 + 한국어 라벨이 자연이미지
  사전학습과 어긋나기** 때문이었다(sanity 3종으로 버그를 배제한 뒤 내린 결론).
- 방향 문항이 4개뿐인 이유는 게으름이 아니라 **정수기·공기청정기 매뉴얼은 회전 방향을 본문에 적고
  청소기만 도면에 맡기기** 때문이었다. 크로스모달이 필요한 지점은 제품군마다 다르다.

두 발견 모두 "일반적인 멀티모달 RAG 베스트프랙티스"에서는 나오지 않는다. 데이터를 직접 열어봐야 나온다.

## 3. 가장 큰 실수와 교훈 — 9주차 하네스 미검증 사건

**무슨 일이 있었나.** 9주차 1차 구현에서 rasterize → 캡션 → CLIP → 비교 하네스까지 코드를 다 만들고,
결과 수치를 뽑고, `week9_evaluation.md`에 findings까지 썼다. 수치는 "C1 ≤ C0", "캡션은 도움 안 됨",
"CLIP 12% = 한국어 도면 OOD"였다. 그럴듯한 결론이었다.

**전부 아티팩트였다.** 재검토에서 드러난 것(`docs/WEEK9_DEFECTS.md`):

- **D1**: C0가 프로젝트 기준선(ADR-011 page match 25%)을 재현하지 못했다(75%로 나옴).
  `page_hit`를 **ADR-011 정의를 확인하지 않고 새로 만든 ad-hoc 정의**로 쟀기 때문이다.
- **D2**: "캡션 무용"은 캡션 품질 문제가 아니라 **검색 실패**였다. 정답 페이지의 캡션이 top-5에
  든 경우가 **2/8**뿐이었다. 캡션 내용은 시험대에 오르지도 못했다.
  게다가 "C1이 캡션 덕에 답을 바꿨다"고 본 IR-A3는 **top-5가 전부 텍스트 청크**였다 — 답변을 보고
  캡션 사용을 추론한 오판이었다.
- **D3**: CLIP 12%는 모든 페이지 score가 0.27 근처로 평탄한 **버그 시그니처**였는데 sanity check를
  0회 했다. (재검토 후 버그는 아니었지만, 그건 확인하고 나서야 할 수 있는 말이다.)
- **D4**: judge가 "앞면 상단"이 정답인 문항에서 "앞면"만 답한 것을 통과시켰다.

**교훈.** `docs_to_pages`가 `modality`를 버리고 있었기 때문에 **"캡션이 검색됐는지" 자체를 볼 수
없었다.** 즉 하네스가 측정하려는 대상을 측정하지 못하는 상태였는데, 그걸 모른 채 결론을 썼다.

> **평가 하네스는 검증 대상이지 도구가 아니다.**
> 새 지표를 만들면 (a) 기존 기준선을 재현하는지 먼저 확인하고, (b) 자명한 케이스로 sanity check를
> 하고, (c) 중간 상태(어떤 청크가 실제로 컨텍스트에 들어갔는지)를 반드시 기록한다.

이 교훈을 12주차에 그대로 적용했다: `week12_eval`은 모든 문항의 **retrieved context 전문**을
저장한다. 덕분에 실패를 F-CROP(정보 없음)과 F-GEN(정보 있는데 못 씀)으로 나눌 수 있었고,
"영역 캡션의 한계"와 "생성의 한계"를 섞어서 말하지 않을 수 있었다. 이번 주 채점 중에도
IR-V4의 원인을 처음에 F-CROP으로 짐작했다가, 컨텍스트를 열어보고 **F-GEN**으로 정정했다.

## 4. 다시 한다면

1. **평가셋을 3주차에 크게 만든다.** image-required 27문항을 12주차에 만든 것이 이 프로젝트의
   가장 큰 순서 실수다. 9주차·11주차의 결론이 전부 n=1에 걸린 근본 원인이 이것이다.
   문항을 먼저 만들었다면 Week 9의 아티팩트 결론도 애초에 걸러졌을 것이다.
2. **중간 상태 로깅을 처음부터 1급으로 둔다.** "무엇이 컨텍스트에 들어갔는가"를 기록하지 않으면
   실패 원인 분류가 불가능하고, 실패 원인을 모르면 다음 개선을 고를 수 없다.
3. **자동 지표를 신뢰하기 전에 몇 건은 손으로 채점해 본다.** Week 9의 엄격 judge는 골든셋 결함
   때문에 정답을 0점 처리했고(D6), 관대한 judge는 디테일 누락을 통과시켰다(D4). 12주차에
   RAGAS·LLM judge를 버리고 수동 채점으로 간 것은 이 두 실패의 결과다.
4. **simple/complex 페어를 처음부터 평가에 넣는다.** v3까지 image-required가 complex 3종에만
   있어서 "복잡한 매뉴얼에서만 되는 기법인가?"를 11주 동안 답할 수 없었다.

## 5. 남은 과제 (닫으면서 명시)

- **방향 유형 0/4** — 화살표 기하를 문장이 아니라 구조화 필드로 뽑는 접근 필요.
- **F-GEN 6건** — 생성 프롬프트가 캡션의 구조화 필드를 근거로 인정하도록 보강.
- **영역 검출** — 지시선으로 이어진 합성 도면이 한 덩어리로 묶여 inset이 분리되지 않는다
  (dilate 0/1/2 전부 확인, 현재 값이 최선).
- **모델 라우팅** — simple/complex 페어에서 잘못된 매뉴얼을 검색(IR-W6). Self-Query를 모델명→복잡도
  매핑으로 확장하는 안이 `docs/WEEK11_ARCHITECTURE.md` §6에 있다.
- **크롭 전면 확장 미측정** — 영역 캡션은 15페이지에만 있다. 252페이지로 넓혔을 때의 성능은 모른다.

## 6. 한 문장으로

**"텍스트만으로는 매뉴얼 도면 질문에 0/27이었고, 영역 단위 VLM 캡션으로 8/27이 되었다 —
아이콘은 뚫렸고 방향은 아직이다."** 12주 동안 이 한 문장을 *정직하게* 말할 수 있는 상태를 만드는 것이
목표였고, 거기까지는 왔다.
