# Week 9 평가 (재작업판) — 크로스모달 RAG 비교 C0 / C1 / C1cap / C2

> 실험 명세: `docs/WEEK9_TASKS.md` + 재작업 계획 `docs/WEEK9_REWORK_PLAN.md` (결함 목록 `docs/WEEK9_DEFECTS.md`).
> 원자료: `data/week9_results.json` (+ per-config `data/week9_rows_*.json`).
> 재현: `python -m src.week9_eval C0|C1|C1cap|C2` (스테이지별 프로세스, 문항 단위 체크포인트) → `merge`.
> **1차(2026-06-30) 결과는 전량 폐기** — 하네스가 측정 대상을 측정하지 않았음(DEFECTS D1~D7·E1~E9). 본 문서가 유일한 유효 결과다.

## 0. TL;DR

1. **검색 구조 수정(modality-aware retrieval)은 작동했다.** 정답 페이지 캡션의 top-5 진입(caption-hit)이 2/8 → **6/8(75%)**. 1차의 "캡션 무용"은 캡션이 컨텍스트에 들어오지도 못한 상태의 artifact였음이 확정.
2. **캡션은 이 도메인에서 유일하게 작동하는 cross-modal 검색 매체다.** 캡션-only 검색(C1cap)의 IR8 page-hit **75%** vs CLIP **12%**(sanity 검증으로 버그 아님 확정 — §5).
3. **answer 층에서 C1이 C0를 처음으로 실질적으로 이겼다 — 단 1문항 차이다.** 수동 채점 기준 C1 2/8 vs C0 1/8. 유일한 순수 이득(IR-W1)이 정확히 목표했던 패턴: 본문에 없는 도면 전용 정보(①=중금속9 흡착 필터)를 캡션이 운반, C0는 거절 / C1은 정답.
4. **잔여 6/8 실패의 병목은 검색이 아니라 캡션 내용이다.** 전체 페이지 150dpi + gpt-4o로도 미세 아이콘 모양·부품의 공간 위치는 캡션에 담기지 않는다(§4). → 10주차 영역 crop(bbox 기반 영역 캡션)의 데이터 근거.
5. **신뢰 토대 확립:** C0의 citation 층이 ADR-011 앵커(model 50%/page 25%)를 **정확히 재현** — 하네스가 프로젝트 기준선과 같은 언어로 말한다. retrieval 층과 citation 층은 분리 보고(혼동 금지).

## 1. 1차 대비 바뀐 것 (요약)

| 축 | 1차 (폐기) | 재작업판 |
|---|---|---|

| 캡션 | gpt-4o-mini, 95dpi, 슬롯 강제 프롬프트(환각·콜아웃 오매핑) | **gpt-4o, 150dpi, v2 프롬프트**(있는 것만·라벨 원문 전사·모양 묘사) — 파일럿에서 p18 콜아웃 9/9 정확 |
| 지표 | page_hit 단일(층 혼동) | **3층 분리**: retrieval page-hit / citation(Week7 정의) / answer(엄격 judge + 수동채점) |

| C2a answer | 하드코딩 0을 측정치처럼 보고 | **n/a by design** (읽기 단계 없음) |
| 골든셋 | 미감사 | **IR8 라벨 audit**: IR-W2 강등(답이 본문에 존재), IR-W1 GT 구체화(중금속9 흡착 필터)+질문에 '정수기' 명시, Q08 ref p10→p24 수정(D6은 골든셋 결함이었음) |

캡션 비용 정정: 1차의 "페이지당 ~26k tok"은 gpt-4o-mini의 이미지 과금 특성(4o의 ~34배)이었다. gpt-4o 기준 페이지당 ~1.1k tok → 252페이지 전량 재캡션 ≈ $3~5.

## 2. 결과 — 3층 분리 (IR8 = 감사 후 8문항, 대조 = 순수 text-only 6)

### 2.1 Retrieval 층

| 구성 | IR8 page-hit ±2 (±0) | IR8 caption-hit | 비고 |
|---|---|---|---|
| C0 텍스트-only | **75%** (62%) | n/a | 텍스트만으로 페이지는 잘 찾음 |
| C1 modality-aware | **75%** (62%) | **75%** | 캡션이 처음으로 컨텍스트에 진입 (1차 25%) |
| C1cap 캡션-only | **75%** (62%) | 75% | **캡션 단독으로도 C0급 검색** |
| C2a/C2b CLIP | 12% | n/a | §5 sanity: 버그 아님, 도메인 부적합 |

### 2.2 Citation 층 (Week 7 정의 — ADR-011 앵커와 비교 가능)

| 구성 | IR8 model match | IR8 page match |
|---|---|---|
| ADR-011 앵커 (Week 7 text-only) | 50% | 25% |
| **C0 (재현 확인)** | **50%** ✅ | **25%** ✅ |
| C1 | **62%** | **38%** |
| C1cap | 25% | 0% |

C0의 정확한 앵커 재현이 이 표 전체의 신뢰 근거다. C1의 +12%p/+13%p는 캡션 청크가 페이지 태그를 달고 들어와 인용 정확도까지 끌어올림을 시사(n=8, 1문항=12.5%p 주의).

### 2.3 Answer 층 (엄격 judge, 부분일치=0 / **수동채점 병행**)

| 구성 | IR8 judge | IR8 수동 | 대조(6) judge | 대조(6) 수동 |
|---|---|---|---|---|
| C0 | 0/8 | **1/8** | 0/6 | **3/6** |
| C1 | **1/8** | **2/8** | 0/6 | **4/6** |
| C1cap | 0/8 | 1/8 | 0/6 | (3~4/6, C0와 동질) |
| C2b | 0/8 | 0/8 | 0/6 | 0/6 |

수동채점 기준 = "매뉴얼 충실성"(GT 문자열이 아니라 원본 매뉴얼 대비 사실 일치). judge-수동 불일치는 §6.

## 3. IR8 문항별 판정 (수동채점 근거)

| 문항 | C0 | C1 | 원인 진단 |
|---|---|---|---|
| IR-A1 조작부 위치 | 거절 | 거절 (캡션 hit) | v2 캡션이 라벨은 전사하나 **공간 위치를 서술하지 않음** — v2 프롬프트의 트레이드오프(§4) |
| IR-A2 상태표시부 위치 | "앞면"만(0) | 거절 | 동일. 엄격 judge가 1차의 오통과("앞면"=1)를 교정 |
| IR-A3 공기제균 아이콘 | 거절 | 거절 (캡션 hit) | 캡션이 표 행은 전사하나 **표 안 미세 아이콘 모양은 못 읽음**(150dpi 한계) |
| **IR-W1 왼쪽 필터** | 거절 | **정답** ✅ | **캡션이 도면 전용 정보(①=중금속9 흡착 필터)를 운반** — 목표 패턴의 첫 실증 |
| IR-W2 화살표 맞춤면 | 정답(수동) | 정답(수동) | 감사에서 강등된 문항 — 답이 본문에 있어 캡션 불필요 |
| IR-V1 흡입구 위치 | 모호(0) | 모호(0) | 검색이 p15를 놓침(cap-hit F) + 캡션도 끝단 정보 없음 |
| IR-V2 걸이 방향 | 거절 | 오답(주체 혼동) | 방향 정보가 캡션에 없음("방향을 가리킴"까지만 서술) |
| IR-V3 Wi-Fi 끊김 아이콘 | **"Y" 환각** | "X 표시"(0) | C0의 Y는 pymupdf가 아이콘 글리프를 문자 Y로 추출한 artifact(본문 확인). C1은 근접 오답 — 빗금(사선)을 캡션이 누락 |

읽는 법: **검색은 이제 대부분 성공한다(캡션 hit 6/8). 실패 6건 중 5건은 "캡션에 그 내용이 없다"가 원인** — 아이콘 모양·공간 위치·회전 방향. 전체 페이지 캡션의 내용 상한이며, 영역 crop(가득 채운 아이콘 1개를 읽히는 방식)으로만 뚫린다.

## 4. 캡션 v2의 성과와 트레이드오프 (정직 기록)

- **성과:** 슬롯 강제 제거로 환각 소멸(없는 제어판/표 발명 0건), 콜아웃 라벨 원문 전사(파일럿 p18 9/9 — v1은 3개 오매핑+2개 누락, 같은 페이지 중복 캐시 2건의 매핑이 서로 달랐던 confabulation 증거 확보). IR-W1 정답의 직접 원천.
- **트레이드오프:** "인쇄된 라벨을 그대로" 원칙이 v1의 공간 위치 서술(상/하/좌/우)을 밀어냈다 → IR-A1/A2에서 위치 답변 불가. **다음 반복: bbox 우선 인식 + 주변 텍스트 기반 JSON 캡션**(영역 단위로 위치·라벨·모양을 구조화) — 10주차 crop과 자연 결합.
- **잔여 한계:** 150dpi 전체 페이지에서는 gpt-4o도 표 안 미세 아이콘(빗금 친 Wi-Fi 부채꼴, 이온 기호)의 모양을 못 읽는다. 파일럿과 본 실행 모두에서 재확인.

## 5. C2 (CLIP) — sanity 검증 후 기각

버그 가설(D3)을 3종 sanity로 검정: ① 이미지→이미지 이웃(air_C p18의 최근접 = 자매 매뉴얼의 같은 도면 페이지, sim 0.93) ✅ ② 영어 거시 쿼리("cylindrical air purifier tower diagram" → 정답 p18 1위, 3.5σ) ✅ ③ **한국어 쿼리 실패 + 아이콘 수준 합성 쿼리는 영어로도 실패**(정수기 페이지로 이탈). → 파이프라인은 정상이고, 실패는 (a) 한국어-이미지 정렬 약함 (b) 페이지 임베딩의 세밀도 상한. **본 도메인 질의에는 부적합으로 기각**(ADR-002 한국어-only 하에서). C2b는 검색 실패가 상류라 late-fusion 자체를 시험하지 못함(전 문항 "이미지에서 확인 불가" — page-hit 조건부 표본 n=1뿐).

## 6. Judge 캘리브레이션 (수동채점 대조)

엄격 judge(gpt-4o, 부분일치=0)는 **방향이 일관된 하한 추정기**다: 불일치 7건 전원이 "judge가 더 엄격"(false negative), 관대한 방향 0건.

| 불일치 | 사유 |
|---|---|
| IR-W2 (C0·C1·C1cap) | 매뉴얼 원문 그대로의 정렬 서술을 "핵심 누락"으로 오판 |
| Q01, Q11, Q19, Q18(C1) | **GT 품질 문제**: Q01 GT가 모델답변보다 덜 정확, Q11 GT(3.5시간)가 매뉴얼(4시간)과 모순, Q19는 모델 미특정으로 simple/complex 매뉴얼의 정답이 다름 |

→ 대조군 GT 정비(golden set v3)가 필요하다는 부산물 발견. Q06의 ref(air_C p.18 '필터 교체하기')도 실제 p18(각 부 명칭)과 불일치 의심. **judge 수치는 하한, 수동 수치가 본선**으로 읽을 것. (부가 관찰: 답변 모델이 거절 시 프롬프트의 플레이스홀더 "(출처: 제품_복잡도 p.페이지)"를 그대로 되뱉음 — 무해하나 인용 파서에 안 잡히는 형태.)

## 7. 결론 — "추론 필요시 VLM" 가설의 현재 상태

- ✅ **VLM 없이는 cross-modal 검색 자체가 성립하지 않는다**: CLIP 12% vs VLM 캡션 75% (검색 매체로서의 VLM).
- ✅ **VLM 오프라인 추론(캡션)이 도면 전용 정보를 답으로 연결한 첫 실증**: IR-W1 (C0 거절 → C1 정답). 단 **n=1** — 방향 증거이지 결론이 아님.
- ⚠️ **전체 페이지 캡션의 내용 상한이 지배적 병목**(6/8): 아이콘 모양·공간 위치·방향은 페이지 단위 캡션에 안 담긴다. "VLM이 필요하다"는 "**영역 단위로** VLM을 써야 한다"로 정밀화됨.
- 10주차 입력: **bbox/영역 crop 캡션(JSON 구조화)** + 대조군 GT 정비(v3) + (선택) IR-V3류를 위한 고해상 crop 재캡션. ADR-012는 crop 결과까지 본 뒤 판단.
